## What the app is

A market-opportunity scanner (Scanner / Sector Rotation / Backtesting) running
on a simulated dataset — 63 fictional companies, 2016–2026 daily data,
generated by `backend/app/seed.py`. Ten named strategies, a 7-factor scoring
system, and a point-in-time backtester with no look-ahead bias. Full detail
in `README.md`.

## Build history

### Local setup & first deploy
- Unzipped from `~/Downloads/stockfind-pro.zip`; needed Python 3.10+ (system
  Python was 3.9.6) — installed Python 3.12 via Homebrew.
- `requirements.txt` was missing `scipy` (needed by `data_gen.py`) — added it.
- `git init`'d locally, pushed to a **new** repo `AI-Consultant-2026/stockfind-pro`
  after an earlier mixup where it briefly overwrote the unrelated
  `AI-Consultant-2026/StockFinderPro` (Node/TS scaffold) repo — reverted, and

- Deployed to Render. Render dropped `runtime.txt` support mid-session —
  switched to `PYTHON_VERSION` env var / `.python-version` file.
- Upgraded the Render instance from Free → Starter ($7/mo) to avoid spin-down.

### Accounts & subscription paywall
- Email/password signup & login, hashed passwords, server-side sessions.
- Every data endpoint (`/api/scan`, `/api/radar`, `/api/stock/*`,
  `/api/sectors`, `/api/backtest*`, `/api/universe`) gated server-side:
  `401` logged out, `402` logged in but not subscribed.
- Payment is a **placeholder gateway** — "Subscribe" just flips a DB flag,
  no real processor. Monthly ($19) / Annual ($179) plans.

### Persistent disk & deploy incidents
- Added a 1GB Render disk at `/var/data` (`DB_DIR` env var) so accounts
  survive redeploys instead of resetting on every build.
- Hit two real deploy failures from this:
  1. Seeding the DB in the **Build Command** doesn't work — the disk isn't
     mounted during build, only at runtime. Moved seeding into the
     **Pre-Deploy Command** instead (`test -f "$DB_DIR/stockfind.db" ||
     python -m app.seed`).
  2. A stripped-down Build Command shipped before the Pre-Deploy Command
     saved, so a deploy briefly crashed on a fresh empty disk
     (`no such table: companies`). Render's settings-save API was also down
     (confirmed genuine `503` via network inspection, not a rate limit) —
     worked around it by seeding the disk directly through Render's Shell.
- Fixed `main.py` to always re-run schema migrations at startup (not just
  when the DB file is missing), since `CREATE TABLE IF NOT EXISTS` alone
  doesn't retroactively add new columns/tables to an already-seeded DB.
  Added `_ensure_column()` in `database.py` for idempotent `ALTER TABLE`s.
- **Known fragility:** attaching the disk disabled zero-downtime deploys —
  every deploy now has a brief `502` window. SQLite-on-a-single-disk has
  already caused two incidents; moving to managed Postgres would remove
  this whole class of problem (see Open Items).

### Admin dashboard (`/admin`)
- Fully separate auth from regular users — `ADMIN_EMAIL` / `ADMIN_PASSWORD`
  env vars, own session key, own `admin_required` decorator.
- Stats: total/subscribed/free users, active in last 7d, signups today/7d,
  backtests run (7d).
- Searchable user table with Grant/Revoke (comps or revokes a subscription
  without touching payment) and a **Last Active** column.
- **Top Stocks** panel — most-viewed tickers, last 7 days.
- Real **Activity Log** (`activity_log` table): signup, login,
  subscribe/unsubscribe, scanner searches (filters used), stock views, tab
  switches, backtest runs, admin actions — all timestamped.
- Admin password was regenerated once (original had visually ambiguous
  characters — `l`/`I`/`1` — that were likely mistyped) and the admin email
  was changed from `hellocareconsulting@gmail.com` to
  `info@hellocareconsulting.com` to avoid overlap with other systems using
  that address.
